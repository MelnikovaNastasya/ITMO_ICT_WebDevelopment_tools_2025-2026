    Лабораторная работа №1¶

    Реализация серверного приложения на FastAPI¶

    Тема: разработка программы-тайм-менеджера TimeFlow
    Цель работы: разработать серверное приложение на FastAPI с использованием PostgreSQL, SQLAlchemy, Alembic и JWT-аутентификации.

    1. Описание проекта¶

    TimeFlow — серверное приложение для планирования задач и учёта времени. Пользователь может зарегистрироваться, войти в систему, создавать проекты и задачи, назначать задачам теги, устанавливать дедлайны и учитывать затраченное время.

    Все пользовательские данные защищены. Пользователь может просматривать, изменять и удалять только собственные задачи, проекты, теги и записи времени.

    В проекте использованы:

    • Python;
    • FastAPI;
    • PostgreSQL;
    • SQLAlchemy 2.0;
    • Alembic;
    • Pydantic;
    • JWT;
    • Argon2;
    • Pytest.

    2. Структура проекта¶

## 3. Модель базы данных

В приложении реализовано шесть таблиц:

1. `users` — пользователи;
2. `projects` — проекты;
3. `tasks` — задачи;
4. `tags` — теги;
5. `task_tags` — связь задач и тегов;
6. `time_entries` — записи затраченного времени.

В проекте используются связи one-to-many:

* один пользователь может иметь несколько проектов;
* один пользователь может иметь несколько задач;
* один проект может содержать несколько задач;
* одна задача может иметь несколько записей времени.

Связь many-to-many реализована между задачами и тегами. Одна задача может иметь несколько тегов, а один тег может относиться к нескольким задачам.

Ассоциативная таблица `task_tags` содержит поля `task_id`, `tag_id` и дополнительное поле `added_at`, которое хранит время назначения тега задаче.

```python
class TaskTag(Base):
    __tablename__ = "task_tags"

    task_id: Mapped[int] = mapped_column(
        ForeignKey("tasks.id", ondelete="CASCADE"),
        primary_key=True
    )

    tag_id: Mapped[int] = mapped_column(
        ForeignKey("tags.id", ondelete="CASCADE"),
        primary_key=True
    )

    added_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
        default=utcnow
    )

    Полный код моделей:

    [app/models/entities.py]

    4. Подключение к PostgreSQL¶

    Для хранения данных используется PostgreSQL. Адрес базы данных передаётся через переменную окружения DATABASE_URL.

    Пример файла .env.example:

    DATABASE_URL=postgresql+psycopg://postgres:postgres@localhost:5432/timeflow
JWT_SECRET=replace-with-a-long-random-secret
ACCESS_TOKEN_EXPIRE_MINUTES=60

    Подключение к базе данных:

    engine = create_engine(
    settings.database_url,
    pool_pre_ping=True
)

SessionLocal = sessionmaker(
    bind=engine,
    autoflush=False,
    expire_on_commit=False
)


def get_db():
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()

    Настоящий файл .env добавлен в .gitignore, поэтому пароль базы данных и секретный ключ JWT не загружаются в открытый репозиторий.

    Полный код подключения:

    [app/db/database.py]

    5. Миграции Alembic¶

    Для управления структурой базы данных используется Alembic.

    Начальная миграция создаёт все шесть таблиц, внешние ключи, индексы, ограничения уникальности и перечисления статусов и приоритетов.

    Применение миграций:

    alembic upgrade head

    Создание новой миграции:

    alembic revision --autogenerate -m "описание изменения"

    Файлы миграций:

    [alembic]

    6. Регистрация и авторизация¶

    Для регистрации используется метод:

    POST /auth/register

    Пользователь передаёт электронную почту, имя пользователя и пароль. Перед сохранением пароль хэшируется с помощью алгоритма Argon2.

    Пароль не возвращается в ответах API.

    Для входа используется метод:

    POST /auth/login

    После проверки имени пользователя и пароля сервер создаёт JWT-токен.

    В поле sub сохраняется идентификатор пользователя, а в поле exp — время окончания действия токена.

    def create_access_token(user_id: int) -> str:
    expires = datetime.now(timezone.utc) + timedelta(
        minutes=settings.access_token_expire_minutes
    )

    return jwt.encode(
        {"sub": str(user_id), "exp": expires},
        settings.jwt_secret,
        algorithm=settings.jwt_algorithm,
    )

    При обращении к защищённым методам токен передаётся в заголовке:

    Authorization: Bearer <JWT-токен>

    Готовые системы авторизации не используются. Генерация и проверка JWT реализованы вручную.

    Код безопасности:

    [app/core/security.py]

    [app/api/dependencies.py]

    7. API пользователей¶

    Метод Адрес Назначение
    POST /auth/register регистрация
    POST /auth/login получение JWT
    GET /users/me получение текущего пользователя
    GET /users получение списка пользователей
    PATCH /users/me/password смена пароля

    При смене пароля пользователь должен указать старый пароль. Новый пароль сохраняется только в виде хэша.

    8. API проектов¶

    Для проектов реализованы CRUD-операции:

    Метод Адрес Назначение
    GET /projects получить проекты пользователя
    POST /projects создать проект
    GET /projects/{project_id} получить один проект
    PATCH /projects/{project_id} изменить проект
    DELETE /projects/{project_id} удалить проект

    При получении проекта сервер возвращает вложенный список его задач. Это демонстрирует связь one-to-many.

    9. API задач¶

    Для задач реализованы следующие методы:

    Метод Адрес Назначение
    GET /tasks получить список задач
    POST /tasks создать задачу
    GET /tasks/{task_id} получить одну задачу
    PATCH /tasks/{task_id} изменить задачу
    DELETE /tasks/{task_id} удалить задачу

    Задача содержит:

    • название;
    • описание;
    • статус;
    • приоритет;
    • дедлайн;
    • проект;
    • дату создания;
    • дату изменения.

    Доступна фильтрация задач по статусу, приоритету и дедлайну.

    При получении задачи возвращаются вложенные объекты:

    • проект;
    • список тегов;
    • список записей времени.

    10. Теги и связь many-to-many¶

    Для работы с тегами реализованы методы:

    Метод Адрес Назначение
    GET /tags получить теги пользователя
    POST /tags создать тег
    DELETE /tags/{tag_id} удалить тег
    POST /tasks/{task_id}/tags/{tag_id} назначить тег задаче
    DELETE /tasks/{task_id}/tags/{tag_id} удалить тег у задачи

    Одинаковые теги нельзя повторно создавать для одного пользователя. В этом случае сервер возвращает ошибку 409 Conflict.

    После назначения тега он отображается как вложенный объект в задаче.

    11. Учёт времени¶

    Для каждой задачи можно создавать записи затраченного времени.

    Метод Адрес Назначение
    GET /tasks/{task_id}/time получить записи времени
    POST /tasks/{task_id}/time добавить запись времени

    Пользователь указывает время начала и окончания работы. Продолжительность вычисляется сервером в минутах.

    Например, для периода с 10:00 до 11:30 значение duration_minutes равно 90.

    12. Защита пользовательских данных¶

    Все операции проверяют владельца объекта.

    Пользователь может просматривать, изменять и удалять только собственные проекты, задачи, теги и записи времени.

    При попытке получить чужую задачу сервер возвращает ошибку 404.

    Также выполнены следующие требования безопасности:

    • пароли не сохраняются в открытом виде;
    • пароли не возвращаются через API;
    • используется Argon2;
    • JWT имеет ограниченный срок действия;
    • секретный ключ хранится в .env;
    • email и username пользователя уникальны.

    13. Swagger¶

    FastAPI автоматически создаёт интерактивную документацию Swagger.

    После запуска приложения она доступна по адресу:

    http://127.0.0.1:8000/docs

    Swagger позволяет просматривать все API-методы, выполнять авторизацию и отправлять тестовые запросы.

    Запуск приложения:

    python -m uvicorn app.main:app --reload

    14. Тестирование¶

    В проекте реализованы автоматические тесты Pytest.

    Тесты проверяют:

    • регистрацию;
    • авторизацию;
    • получение текущего пользователя;
    • CRUD задач;
    • связь задачи и тега;
    • учёт времени;
    • запрет доступа к чужой задаче.

    Запуск тестов:

    pytest -q

    Результат:

    4 passed

    Все автоматические тесты были успешно пройдены.

    16. Вывод¶

    В ходе лабораторной работы было разработано серверное приложение TimeFlow на FastAPI.

    В приложении реализованы шесть таблиц, связи one-to-many и many-to-many, CRUD-операции, вложенное отображение связанных объектов, фильтрация задач и учёт затраченного времени.

    Также реализованы регистрация, авторизация, ручная генерация и проверка JWT-токенов, хэширование паролей, получение информации о пользователе, список пользователей и смена пароля.

    Для хранения данных используется PostgreSQL, а изменение структуры базы выполняется с помощью Alembic.

    Работоспособность приложения подтверждена проверкой API через Swagger и успешным прохождением автоматических тестов Pytest.
