    Лабораторная работа №2¶

    Потоки, процессы и асинхронность¶

    Выполнила: Мельникова Настасья, группа К3341
    Тема: потоки, процессы и асинхронность в Python.

    Цель работы¶

    Изучить отличия между потоками, процессами и асинхронным выполнением в Python, а также сравнить их эффективность при выполнении вычислительных и сетевых задач.

    1. Используемые подходы¶

    Threading¶

    Модуль threading позволяет создавать несколько потоков внутри одного процесса.

    Потоки используют общую память, поэтому между ними относительно легко передавать данные. Из-за существования GIL потоки не обеспечивают полноценного параллельного выполнения тяжёлого Python-кода, но хорошо подходят для операций ввода-вывода:

    • сетевых запросов;
    • работы с файлами;
    • ожидания ответа базы данных.

    Multiprocessing¶

    Модуль multiprocessing создаёт отдельные процессы.

    У каждого процесса есть собственная область памяти и отдельный интерпретатор Python. Благодаря этому процессы могут выполнять вычисления одновременно на разных ядрах процессора и не ограничиваются GIL.

    Недостатками являются дополнительные затраты на создание процессов и передачу данных между ними.

    Asyncio¶

    asyncio реализует асинхронное выполнение с помощью цикла событий и корутин.

    Когда одна корутина ожидает завершения сетевого запроса, цикл событий может продолжить выполнение других корутин. Такой подход особенно эффективен при большом количестве операций ввода-вывода.

    Само по себе asyncio не ускоряет тяжёлые вычисления, поскольку обычно работает в одном потоке.

    Подход Способ выполнения Общая память Основное применение
    threading несколько потоков одного процесса да сетевые и файловые операции
    multiprocessing отдельные процессы нет тяжёлые вычисления
    asyncio корутины и цикл событий да большое количество сетевых запросов

    Задача 1. Вычисление суммы¶

    2. Постановка задачи¶

    Необходимо написать три программы с использованием:

    • threading;
    • multiprocessing;
    • asyncio.

    Каждая программа должна вычислить сумму всех чисел от 1 до:

    10 000 000 000 000

    Диапазон необходимо разделить на несколько частей и выполнить обработку этих частей параллельно или конкурентно.

    3. Общая функция вычисления суммы¶

    Во всех трёх программах используется функция calculate_sum():

    def calculate_sum(start: int, end: int) -> int:
    if start > end:
        return 0

    return (start + end) * (end - start + 1) // 2

    Для вычисления применяется формула суммы арифметической прогрессии.

    Последовательный перебор десяти триллионов чисел занял бы непрактично большое время. Использование формулы позволяет получить точный результат за короткое время.

    Исходный диапазон делится на четыре непересекающиеся части. После выполнения подзадач частичные суммы складываются.

    Правильный результат:

    50000000000005000000000000

    4. Реализация с помощью Threading¶

    В потоковом варианте создаются четыре объекта Thread.

    Каждый поток получает отдельную часть диапазона и сохраняет вычисленную сумму в определённую позицию общего списка.

    threads = [
    threading.Thread(
        target=worker,
        args=(index, start, end)
    )
    for index, (start, end) in enumerate(ranges)
]

for thread in threads:
    thread.start()

for thread in threads:
    thread.join()

    Метод start() запускает поток, а join() заставляет основную программу дождаться его завершения.

    5. Реализация с помощью Multiprocessing¶

    В этом варианте создаётся пул из четырёх отдельных процессов.

    with multiprocessing.Pool(processes=workers) as pool:
    partial_results = pool.starmap(
        calculate_sum,
        ranges
    )

    Каждый процесс получает отдельный диапазон. После выполнения starmap() возвращает частичные результаты, которые складываются в общую сумму.

    Процессы имеют собственную память и могут одновременно выполнять Python-код на разных ядрах процессора.

    6. Реализация с помощью Asyncio¶

    Для асинхронного варианта создаются четыре корутины.

    partial_results = await asyncio.gather(
    *(
        calculate_sum_async(start, end)
        for start, end in ranges
    )
)

    asyncio.gather() запускает корутины конкурентно и ожидает их завершения.

    Асинхронность не предоставляет преимущества для короткого вычисления, однако этот вариант демонстрирует применение async, await и цикла событий.

    7. Результаты задачи 1¶

    Замеры были выполнены на одном компьютере с одинаковым количеством подзадач.

    Подход Время выполнения Полученная сумма Результат
    Threading 0.000192 сек. 50000000000005000000000000 верный
    Multiprocessing 0.066741 сек. 50000000000005000000000000 верный
    Asyncio 0.000597 сек. 50000000000005000000000000 верный

    Анализ результатов¶

    Самым быстрым в данном запуске оказался threading, а самым медленным — multiprocessing.

    Это не означает, что потоки всегда быстрее процессов. В данной реализации каждая часть суммы вычисляется практически мгновенно по математической формуле.

    Большая часть времени multiprocessing была потрачена не на вычисление, а на создание отдельных процессов и организацию взаимодействия между ними.

    Для действительно тяжёлой вычислительной задачи наиболее подходящим вариантом был бы multiprocessing, поскольку процессы могут использовать несколько ядер процессора и не ограничиваются GIL.

    Задача 2. Параллельный парсинг веб-страниц¶

    8. Постановка задачи¶

    Необходимо создать три программы для параллельной загрузки нескольких веб-страниц.

    Каждая программа должна:

    1. загрузить HTML-страницу;
    2. найти её заголовок <title>;
    3. сохранить заголовок в базу данных PostgreSQL;
    4. вывести результат в терминал;
    5. измерить общее время выполнения.

    Для работы использована база данных TimeFlow из лабораторной работы №1.

    9. Список страниц¶

    Для парсинга использовались следующие страницы:

    https://example.com/
https://www.iana.org/help/example-domains
https://www.python.org/
https://fastapi.tiangolo.com/
https://docs.python.org/3/library/asyncio.html
https://docs.python.org/3/library/threading.html

    Из каждой страницы извлекается содержимое HTML-тега <title>.

    10. Сохранение результатов¶

    Полученные заголовки сохраняются в существующую таблицу tasks базы данных TimeFlow.

    Каждая страница создаёт отдельную задачу:

    • title — заголовок страницы;
    • description — URL страницы и использованный подход;
    • status — planned;
    • priority — low;
    • user_id — идентификатор пользователя TimeFlow.

    Пример SQL-запроса:

        user_id,

        title,

        status,

        deadline,

    Таким образом, лабораторная работа №2 использует PostgreSQL и таблицы, созданные в лабораторной работе №1.

    11. Парсинг с помощью Threading¶

    Список URL делится между четырьмя потоками.

    Каждый поток последовательно обрабатывает полученную часть списка. Для выполнения HTTP-запросов используется библиотека requests.

    threads = [
    threading.Thread(
        target=parse_chunk,
        args=(chunk,)
    )
    for chunk in chunks
]

    Во время ожидания ответа одного сайта другие потоки могут продолжать работу. Поэтому потоки подходят для сетевых операций.

    Полученное время:

    1.466 сек.

    12. Парсинг с помощью Multiprocessing¶

    Для обработки страниц создаются отдельные процессы.

    processes = [
    multiprocessing.Process(
        target=parse_chunk,
        args=(chunk,)
    )
    for chunk in chunks
]

    Каждый процесс самостоятельно:

    • загружает страницы;
    • извлекает заголовки;
    • создаёт подключение к PostgreSQL;
    • сохраняет данные.

    Полученное время:

    1.199 сек.

    В данном запуске процессы оказались немного быстрее потоков. Однако результат сетевого теста может меняться в зависимости от скорости интернета и времени ответа сайтов.

    13. Парсинг с помощью Asyncio¶

    В асинхронном варианте используется библиотека aiohttp.

    Для каждого URL создаётся отдельная корутина:

    await asyncio.gather(
    *(
        parse_and_save(url, session)
        for url in URLS
    )
)

    Пока одна корутина ожидает ответ сайта, цикл событий продолжает выполнение остальных корутин.

    Синхронное сохранение в PostgreSQL вынесено в отдельный поток:

    await asyncio.to_thread(
    save_as_task,
    page,
    "asyncio"
)

    Это предотвращает блокировку цикла событий во время обращения к базе данных.

    Полученное время:

    0.741 сек.

    14. Результаты задачи 2¶

    Подход Время выполнения Обработано страниц Результат
    Threading 1.466 сек. 6 успешно
    Multiprocessing 1.199 сек. 6 успешно
    Asyncio 0.741 сек. 6 успешно

    Анализ результатов¶

    Самым быстрым способом оказался asyncio.

    Асинхронная программа отправила несколько запросов, не ожидая последовательного завершения каждого из них. Пока один сайт обрабатывал запрос, программа продолжала работать с другими соединениями.

    Threading также подходит для сетевых операций, но требует создания потоков операционной системы.

    Multiprocessing успешно выполнил задачу, однако для сетевого парсинга отдельные процессы обычно не требуются, поскольку основное время программа ожидает ответы сайтов, а не выполняет сложные вычисления.

    Скорость сетевых программ может отличаться при повторных запусках из-за:

    • качества интернет-соединения;
    • загруженности сайтов;
    • DNS-запросов;
    • установки HTTPS-соединений;
    • кеширования данных.

    17. Вывод¶

    В ходе лабораторной работы были изучены потоки, процессы и асинхронность в Python.

    Все три подхода успешно вычислили сумму чисел от 1 до 10 000 000 000 000 и получили одинаковый правильный результат.

    При вычислении по математической формуле самым медленным оказался multiprocessing, поскольку создание отдельных процессов потребовало больше времени, чем само вычисление.

    Для сетевого парсинга лучший результат показал asyncio — 0.741 секунды. Асинхронность позволила эффективно использовать время ожидания ответов от сайтов.

    Threading также подходит для сетевых операций, поскольку потоки могут переключаться во время ожидания. Multiprocessing лучше использовать для тяжёлых вычислительных задач, способных загрузить несколько ядер процессора.

    Полученные заголовки веб-страниц были успешно сохранены в PostgreSQL в таблицу tasks проекта TimeFlow из лабораторной работы №1.
